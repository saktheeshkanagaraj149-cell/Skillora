# Deploying Skillora

| Part | Host | Cost |
|---|---|---|
| Database | MongoDB Atlas M0 (`cluster0.asbuylc`, already set up) | Free |
| API + Cerbos (`server/`) | Render web service, Docker, Singapore | Free |
| Website (`client/`) | Vercel | Free |

> Render's free plan **sleeps after 15 minutes without traffic**. The first request after that takes about
> 50 seconds while it wakes up. Users stay logged in while it wakes. Upgrade to Starter ($7/month) to keep it always on.

## Before you deploy (checklist)

- [ ] `npm test` passes with Cerbos running (`npm run cerbos --prefix server`), and `npm run test:policies --prefix server` passes
- [ ] `npm run build` passes
- [ ] Courses are built and reviewed in `/admin` (see [COURSES.md](COURSES.md)), then published
- [ ] The admin password is strong (`npm run reset-admin` syncs it from `ADMIN_PASSWORD`)
- [ ] No `.env*` file is committed: `git ls-files | grep .env` should list only the two `.env.example` files

## 1. Atlas (done)
- Network Access must include `0.0.0.0/0`, because Render has no fixed outgoing IP on the free plan.
- Use a strong, auto-generated password for the database user. In `MONGO_URI`, write `@` in the password as `%40`.

## 2. API on Render (Docker: Node API + Cerbos in one container)
`server/Dockerfile` builds one image that runs the Cerbos policy server in the background and the API in front.
The API checks permissions over localhost. If Cerbos stops, protected routes answer 503 (fail closed) and
`/api/health` reports it, so Render restarts the service.

1. Log in at https://render.com **with GitHub**.
2. **New → Blueprint** → choose the `Skillora` repo. Render reads `render.yaml` (runtime `docker`).
   *Already have the service from before Cerbos?* Open it → **Settings** and check that **Runtime is Docker**,
   **Dockerfile Path** is `./server/Dockerfile` and **Docker Build Context** is `./server`. An old Node-runtime
   service won't start Cerbos and every protected route will return 503.
3. **Environment** values:

   | Key | Value |
   |---|---|
   | `MONGO_URI` | Atlas string with `/skillora` before the `?` |
   | `JWT_SECRET` | generated by the Blueprint. Keep it, because changing it logs everyone out |
   | `CLIENT_ORIGIN` | your Vercel URL, no trailing slash (comma-separate several) |
   | `GEMINI_API_KEY` | from https://aistudio.google.com/apikey (needed only for AI course generation) |
   | `YOUTUBE_API_KEY` | Google Cloud → YouTube Data API v3 key (needed only for finding videos) |
   | `NODE_ENV`, `GEMINI_MODEL`, `YOUTUBE_LANGUAGE` | set by `render.yaml` |

   Don't set `CERBOS_URL` or `PORT`: the image and Render provide them.
4. **Apply**. When it shows **Live**, open `https://<service>.onrender.com/api/health`. It should show
   `{"ok":true,"db":"up","authz":"up"}`.

## 3. Website on Vercel
1. https://vercel.com → **Add New → Project** → import `Skillora`.
2. **Root Directory: `client`** (Vite is detected from `vercel.json`).
3. Environment variable: `VITE_API_URL` = `https://<service>.onrender.com/api`
4. **Deploy**, then put the Vercel URL in Render's `CLIENT_ORIGIN` (Render redeploys automatically).

## 4. Fill the courses (once, from a laptop with the real `server/.env`)
```bash
npm run build:courses -- --fresh     # full courses for every skill (Gemini) + as many videos as the YouTube quota allows
npm run build:courses                # the next day(s): finish the videos (~100 lessons a day on the free quota)
npm run build:courses -- --publish   # after reviewing in /admin
```

## 5. Smoke test the live site
- The home page lists 23 skills, and published courses show a count on their cards.
- Register a learner. On a course, check that the lesson video plays and a quiz passes.
- Finish every lesson, fail the final exam once (you see only the score), then pass it to get a certificate.
- Open `/certificate/<ID>` in a private window: it should say **Verified**. Try **Download PDF** too.
- Log in as admin. `/admin` should list the courses, and "Build full course with AI" should work.

## After launch
- Every push to `main` redeploys Vercel. Render redeploys only when something under `server/` changes.
- New skill: add it to `server/src/domains.js`, run `npm run seed`, then `npm run build:courses -- --only=<slug>`.

## What protects production
- **Authorization:** Cerbos policies in `server/cerbos/policies` (80 policy tests). The API fails closed when Cerbos is down.
- **Exam integrity:** a failed exam returns only the score, never which answers were wrong, and each learner can submit 10 attempts per course per hour.
- **Rate limits:** 600 requests per 15 minutes per IP; 20 login or register attempts per 15 minutes; 30 AI generation or "build course" runs per hour.
- **Input:** auth and domain fields must be strings, so objects and arrays can't reach database queries.
- **Headers and CORS:** helmet sets secure headers, and CORS allows only the `CLIENT_ORIGIN` list.
- **Container:** it runs as a non-root user, and `.env*` files are excluded from the image.
- **Startup checks:** the API refuses to start in production without `MONGO_URI`, `JWT_SECRET` or `CLIENT_ORIGIN`, and warns when an optional key is missing.
